# Building PersonaKit, Day 3

I started with a simple review idea:

approve or reject each memory.

That sounded clean.
It was wrong.

The problem is that people do not evaluate memory as a database row. They evaluate it as future behavior.

Some memories are false.
Some are stale.
Some are true, but too private.
Some are true, but only useful if the assistant is directly asked.
Some are badly worded, but the underlying signal matters.

Those should not all collapse into one button called “reject.”

One lesson from building PersonaKit:

The useful question is not only “is this true?”

It is:

Should an assistant be allowed to act on this?
Where?
When?
For whom?
With what level of confidence?

That is why our review model moved beyond approve / reject.

Personal AI memory needs permissions, not just facts.
